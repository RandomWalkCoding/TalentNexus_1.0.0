# 阶段 13：真实验收与最终发布

日期：2026-10-16。分支：`stage/13-production-acceptance`。状态：**已建立执行基线，外部凭据和受控环境验收待执行**。

阶段 13 承接阶段 12 的退出项，不新增业务范围。目标是用真实但隔离的依赖完成 TalentNexus 从组织线索到候选人反馈的闭环，并形成可审阅、可回退的发布单元。

## 验收工作包

| 顺序 | 工作包 | 完成标准 | 证据 |
|---:|---|---|---|
| 1 | 真实供应商接入 | AI、汇率/PPP、Google/Microsoft 使用专用测试凭据；超时、失败、重试、回退快照均有结果 | 脱敏运行记录、provider 版本、快照 ID |
| 2 | 邮箱闭环 | OAuth、审批、发送、重复请求、回信同步、拒绝/退订停止规则通过；不使用个人生产邮箱 | 测试邮箱收发记录、message ID、幂等记录 |
| 3 | 权限与审计 | admin、HR、manager 分别验证允许/拒绝路径；敏感读取、导出、外部任务和失败请求可追溯 | 角色矩阵、requestId、审计样例 |
| 4 | 数据恢复演练 | 隔离副本完成迁移、关键表计数/关联/快照核对；旧应用兼容性和回滚路径通过 | 备份校验和、恢复时间、核对表 |
| 5 | 全链路浏览器验收 | 1440px 与 390px 完成 PRD 场景；加载、空、错、权限、重试、键盘焦点均通过 | 截图、测试报告、浏览器版本 |
| 6 | 性能与发布归档 | 真实规模查询、连接池、登录限制和导出压力有基线；形成不可变制品及回滚点 | 延迟/错误率报告、制品校验和、提交 SHA |

## 执行顺序

1. 创建隔离数据库、测试邮箱、模型和宏观数据 provider 凭据；生产密钥不得复制到恢复环境。
2. 执行 `corepack pnpm lint`、`corepack pnpm typecheck`、`corepack pnpm test`、`corepack pnpm build`，记录完整输出。
3. 使用 `corepack pnpm ops:check -ApiBaseUrl "http://127.0.0.1:3000"`，再按 [部署运维说明](./DEPLOYMENT_RUNBOOK.md) 做迁移、备份、恢复和回滚演练。
4. 运行组织、寻访、薪酬、AI、邮箱和反馈的真实 API/浏览器流程；每一步保存 requestId、快照或 provider ID。
5. 仅在所有工作包通过后创建发布提交和制品；否则保留当前阶段并记录阻塞，不标记生产完成。

## 当前阻塞与边界

- 当前工作区仍包含阶段 08—12 的未提交成果；本阶段不通过切换分支或 reset 清理它们。
- 本阶段不能凭演示适配器替代真实 provider 证据，也不能把本地 `ready` 探针结果当成迁移、恢复或生产就绪证明。
- 需要业务方提供测试邮箱、OAuth 应用、AI provider、汇率/PPP 数据源和批准的测试数据范围后，才能关闭工作包 1、2 和 4。
